1. Resumen y Objetivo del ProyectoEl objetivo principal es el desarrollo de un plugin para WordPress que funcione como un Portal del Empleado modular, integrado profundamente con el ecosistema Microsoft 365 (M365). El Portal debe ofrecer un punto de acceso centralizado a utilidades, comunicación interna, y gestión personal del empleado, siendo completamente usable y administrable desde el Frontend de WordPress.2. Especificaciones Técnicas y Requisitos de Integración ClaveMóduloEspecificación RequeridaIntegración / TecnologíaAutenticación (Login)El acceso al Portal debe ser exclusivamente mediante las credenciales de M365 del empleado.OAuth 2.0 / Azure AD para Single Sign-On (SSO).Usuarios y PerfilesImportación y sincronización bidireccional de datos de usuario (nombre, email, puesto, etc.) desde M365/Azure AD.Microsoft Graph API para importación/exportación de datos.Roles de UsuarioEl sistema debe implementar un sistema de roles y permisos granular dentro del Portal, independiente de los roles nativos de WP, pero mapeable a grupos de Azure AD.Custom Post Types/Taxonomies en WP. Definición de roles: Empleado, Manager, RRHH, Administrador.CalendarioVisualización de eventos de Outlook en el Frontend del Portal. El usuario debe ver su calendario personal y posiblemente calendarios de equipo.Microsoft Graph API (Acceso a Calendarios).Base TecnológicaDesarrollado como un plugin de WordPress. Considerar si las funcionalidades críticas (Firma Electrónica/Tickets) se ejecutan mediante endpoints de Python/Django (para mantener la eficiencia) o se desarrollan puramente en PHP/JS.WordPress PHP / MySQL y considerar integración via API REST (Django/Python) para servicios pesados.3. Módulos y Funcionalidades Específicas3.1. Acceso y Gestión de PerfilLogin SSO: Exigido el inicio de sesión a través de M365.Directorio de Personal: Listado searchable y filtrable de todo el personal (datos de contacto visibles según rol).Edición de Perfil (Frontend): Los empleados pueden editar ciertos campos de su perfil (ej. teléfono personal, foto), con los campos principales sincronizados desde M365 como solo lectura.3.2. Utilidades para EmpleadosZona de Descargas: Módulo para la gestión y descarga de documentos internos (políticas, formularios, nóminas). El acceso a carpetas debe ser controlado por el Sistema de Roles.Aplicación de Firma Electrónica:Permitir la carga de documentos para su firma.Soporte para Certificado Electrónico (Firma Avanzada).Generación automática de Código de Verificación Seguro (CVS) y/o Código QR para la validación de la firma en el documento.3.3. Comunicación y TareasSistema de Anuncios: Módulo para la publicación de comunicados internos, con posibilidad de destacar anuncios importantes ("hola que pasa??" en la mockup).Sistema de Tickets de Mantenimiento:Creación de nuevos tickets desde el Frontend.Visualización del estado de los Mis Tickets Recientes (ej. 'teclado open').Notificación por email (vía M365) sobre cambios de estado.Sistema de Tareas: Módulo simple para la asignación y seguimiento de tareas (posiblemente integración con Microsoft To Do o Planner a futuro).4. Usabilidad y Experiencia de Usuario (UX)Usabilidad en Frontend: Todas las interacciones, desde la creación de un ticket hasta la edición de perfil, deben realizarse sin acceder al backend de WordPress (wp-admin).Diseño Responsivo: El portal debe ser completamente usable en dispositivos móviles (tabletas y smartphones).
